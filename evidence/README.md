# Earthlink Reseller App — Machine Evidence Repository

## Purpose

This directory contains the authoritative, source-bound, machine-generated evidence records for the Earthlink Reseller App.

Under the project invariant rules and **INV-16**, closure of any architectural or synchronization finding is **strictly derived from machine evidence**. Manual claims of `CLOSED` or free-form status edits in markdown or tickets are non-authoritative and prohibited.

---

## Directory Structure

```text
evidence/
├── README.md                          # This specification document
├── baseline_manifest.json             # Canonical baseline git SHA & invariant hashes
├── baseline_test_manifest.json        # Canonical 98-suite certification test manifest
└── <source_sha>/                      # Per-commit sealed evidence records
    ├── closure_bundle.json            # Machine-captured toolchain, test, & pattern data
    ├── closure_result.json            # Derived finding verdicts & evaluation status
    └── CERTIFICATION_REPORT.md        # Machine-rendered Markdown certification report
```

## Artifact Descriptions

### 1. `closure_bundle.json`
Generated by `scripts/collect_closure_evidence.py`. Contains:
- **`source_identity`**: Exact Git commit SHA, branch, working tree dirty status, and `gradlew` repository file mode (100755).
- **`contract_identity`**: SHA256 hashes of `PRODUCTION_INVARIANTS.md`, `contract/closure_contract.yaml`, `contract/invariant_contract.yaml`, `contract/invariant_test_map.yaml`, and `contract/forbidden_patterns.yaml`.
- **`toolchain`**: Host OS, Java version, Gradle version, Kotlin version, and Python runtime.
- **`test_execution`**: Full JUnit XML execution metrics (total tests, passed, failed, errors, skipped, duration) across all 98 test suites.
- **`structural_checks`**: Machine scans for forbidden architectural patterns, invariant mapping consistency, executable bit verification, and release build gates.
- **`artifact_checks`**: SHA256 digests and presence verification for all source files governing invariant findings.

### 2. `closure_result.json`
Generated by `scripts/verify_closure_evidence.py`. Contains:
- Evaluated status (`PASS` / `FAIL`) for every finding in `contract/closure_contract.yaml` (`RC-1` .. `RC-6`, `B6/D-05`, `INV-TEST-MAP-DRIFT`, `COORDINATOR-DIRECT-MUTATION`, `IMPORT-SNAPSHOT-BOUNDARY`, `EVIDENCE-SOURCE-ID`, `WRAPPER-REPRODUCIBILITY`, `VERSION-DRIFT`).
- Derived overall verdict (`READY_FOR_CLOSURE` or `NOT_READY_FOR_CLOSURE`).
- Diagnostic reasons for any failing structural, behavioral, or artifact check.

### 3. `CERTIFICATION_REPORT.md`
Generated by `scripts/render_certification_report.py`. Human-readable Markdown summary displaying cryptographic provenance, executive summary, findings status matrix, and test suite breakdowns directly derived from `closure_result.json`.

## Mandatory Invariants & Rules

1. **No Manual Status Editing:** A finding's status is computed by evaluating the evidence against `contract/closure_contract.yaml`.
2. **Immutable Test Contracts:** Tests must not be skipped, deleted, or weakened. Certification requires 0 failures, 0 errors, and 0 skips.
3. **Exact Source Identity Binding:** If the Git commit SHA changes or files are modified after evidence collection, verification fails.
4. **Fail-Closed Verification:** `scripts/verify_closure_evidence.py` returns exit code `0` if and only if all required checks are present, passing, and source-bound. Any discrepancy returns a non-zero exit code.

---

## How to Execute the Evidence Pipeline

```bash
# 1. Run full test suite and collect evidence bundle
python scripts/collect_closure_evidence.py --run-tests

# 2. Verify evidence against closure contract
python scripts/verify_closure_evidence.py

# 3. Render human-readable certification report
python scripts/render_certification_report.py
```
